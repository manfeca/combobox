Testing prompts

With a screen reader

  • Focus the input does it announce “Combobox” + your label?
  • Open the list does it announce expanded?
  • Arrow down does it read the currently highlighted option (via aria-activedescendant)?
  • Press Enter does it read selection, fill the input, and close?
  • Type to filter do you hear updates?
  • Press Esc does it close and keep focus in the input?

With only keyboard

  • Tab into input, Arrow to move through options, Enter to choose, Esc to dismiss.
  • Tab never lands on individual list items.

Common pitfalls

  • Adding tabindex to options while also using aria-activedescendant (pick one approach).
  • Forgetting to update aria-expanded when the list opens/closes.
  • Rebuilding options without preserving their ids (breaks aria-activedescendant).
  • Using aria-owns to move DOM ownership when simple aria-controls is enough (prefer aria-controls if the popup is a normal sibling/descendant).
